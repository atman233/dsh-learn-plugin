# learn-review：渐进式测验与查漏

## 第零步：定位与选题

1. 找到学习工作区（当前目录或 `~/learn/<主题slug>/` 下的 `plan.md` + `progress.json`）。没有 → 提示先学习。
2. 读取 `progress.json`：已完成的课程、知识点 `mastery`、历史 `weakPoints`、以及是否临近 plan.md 里的里程碑。
3. 出题范围：
   - **临近里程碑（plan.md 中标注的 D 值）**：做跨知识点综合测验；
   - **平时**：优先覆盖最近 1-2 天 + 之前标记为 `weak` 的知识点（各占约一半）；
   - 至少一题来自历史 `weakPoints`——薄弱点不重复考等于没记录。

## 第一步：测验（交互式，一题一题来）

在会话中**一次只出一题，等用户答完再出下一题**。一次全抛出来会让用户扫一眼就跳过，测验就失效了。

题型按渐进加难四档（详见 learn-plan skill 的 `references/method.md` 第五节）：

1. **回忆**：核心机制/定义是什么。
2. **应用**：给一个新情境，要求用概念做判断。
3. **挑错**：给一段看似合理但有漏洞的论述，要求指出错在哪。
4. **反向费曼**（最能检验真理解的题型，每次复习至少一题）：
   - "把 <某个已学概念> 还原成一个不点名的三段式故事"——用户能讲出带取舍的故事，才算真懂；
   - 或"回看 D<NN> 的那个寓言，它漏掉了概念的哪个方面？"

每次复习 4-6 题即可，不要超。

## 第二步：批改与反馈

- **严苛但公平**：直接指出偏差，不客套、不"也对啦"式和稀泥。模糊的回答按不通过处理并说明差在哪。
- 每个薄弱点都必须同时给出**修复路径**：回看哪一天的哪个寓言情节、哪张图、哪一段讲解（引用具体文件与章节，例如"回看 day-02 的'一百个兄弟'情节"）。
- 用户答得好的地方也要点明"这里你确实理解到位了"，让用户知道边界在哪。

## 第三步：写回进度

1. 更新 `progress.json`：
   - 相关知识点 `mastery`（`weak` / `ok` / `solid`）；
   - 新发现的 `weakPoints`（追加，不覆盖历史）；
   - `reviewLog` 追加一条：`{ "date": "<日期>", "score": "<x/y>", "weakPoints": [...], "notes": "..." }`。
2. 如果某知识点连续两次 `weak`：建议在计划中插入一次针对性 mini-lesson（告诉用户下次"继续学习"时你会先补这一块），必要时直接更新 `plan.md` 的日程。

## 第四步：收尾

用两三句话总结：这次复习暴露了什么、下一步建议是什么（继续下一天 / 先加固某点 / 临近里程碑提醒）。让用户清楚地知道下一次该说什么。

## 质量底线

- 不考"背诵原文"，所有应用题的情境必须是文档里没出现过的。
- 反向费曼题不给模板答案——用户讲故事时不要打断；讲完再逐要素点评。
- 进度文件是唯一事实来源：改了口头结论但没写回 progress.json = 这次复习白做。
