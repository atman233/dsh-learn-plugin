# learn-plan：一句话 → 完整学习规划

用户的一句话（如"我想学 Transformer 的注意力机制"）要变成一份**可以照着执行多天**的学习规划。你的产出必须完整到：用户接下来每天只需要说"继续学习"，learn-lesson 就能生成当天的图文课程。

## 第一步：摸底（不要跳过）

用一轮对话（能一次问完就一次问完，不要挤牙膏）向用户确认三件事：

1. **已有基础**：与该主题相关的知识，用户已经会多少？（决定大纲从哪里起步）
2. **学习目标**：是为了面试、做项目、读论文，还是纯兴趣？（决定深度和侧重点）
3. **每日投入**：每天能学多久？（决定每天塞多少内容）

用户如果明确说"别问了，直接出规划"或给出的话题本身已隐含答案，就用合理默认值继续，但必须在 plan.md 顶部**显式标注每一条假设**，例如：

> 【假设】默认你有基本的线性代数和 Python 基础；默认目标是建立直觉而非应试；默认每天投入 45 分钟。如不符请告诉我，我会重排规划。

## 第二步：确定学习工作区

- 默认位置：`~/learn/<主题slug>/`（slug 用小写英文短横线，如 `transformer-attention`；主题名本身是英文时可直接用）。
- 用户指定了位置就用用户的。
- 如果该目录已有 `plan.md`：向用户确认是**继续**（沿用旧规划）还是**重开**（备份旧文件为 `plan.backup.<日期>.md` 后重写）。不要悄悄覆盖。

## 第三步：设计知识点大纲（先拆解，再排期）

把主题拆解成一棵**依赖有序**的知识点树。顺序必须尊重依赖关系（先修知识在前），并且把"理解型知识点"和"操作型技能"区分开。

对每个知识点标注两项元数据，learn-lesson 会据此生成课程：

- **寓言适配**：
  - `fable` —— 有因果结构（有角色、决策、取舍、后果）的概念，适合 Amanda Askell 寓言导入；
  - `variant` —— 纯抽象、无因果结构的概念，标注建议的替代文体（侦探小说 / 未来备忘录 / 童话 / 商业谈判…）；
  - `direct` —— 操作步骤类内容（配置环境、跑代码），不需要寓言，直接讲。
- **配图**：
  - `architecture` / `dataflow` —— 结构、组成、数据流向类；
  - `workflow` / `sequence` —— 过程、步骤、交互时序类；
  - `lifecycle` —— 状态演化类；
  - `none` —— 不适合配图，不要硬画。

判断依据见 `references/method.md`，拿不准时宁可标 `none`，硬凑的图比没有图更碍事。

## 第四步：排日程并写入文件

产出两个文件：

### `plan.md`

```markdown
# 学习规划：<主题名>

> 创建于 <日期> ｜ 目标：<一句话> ｜ 每日投入：<时长> ｜ 预计：<N> 天
> 【假设】<列出所有默认假设，没有则省略此行>

## 学习大纲（知识点 → 天数映射）

| # | 知识点 | 天数 | 先修 | 寓言适配 | 配图 |
|---|--------|------|------|----------|------|
| 1 | xxx    | D1   | -    | fable    | workflow |
| 2 | xxx    | D1   | 1    | direct   | none  |

## 每日日程

### D1（约 <时长>）
- **今天学什么**：<知识点 + 一句话说清学到什么程度算过关>
- **产出物**：<当天课程包含的自测通过 / 一段笔记 / 一个小练习>
- ...

### D2 ...

## 里程碑

- **M1（D<N>）**：<阶段性检验，例如"能不看资料给别人讲清 X">
- ...

## 寓言与图索引

（随课程生成持续更新：每个寓言的载体故事、每张图的文件路径，方便复习时快速回看）
```

### `progress.json`

```json
{
  "topic": "<主题名>",
  "createdAt": "<日期>",
  "dailyMinutes": <数字>,
  "days": [
    { "day": 1, "status": "pending", "completedAt": null, "weakPoints": [] }
  ],
  "knowledgePoints": [
    { "name": "<知识点>", "day": 1, "mastery": "unknown" }
  ],
  "weakPoints": [],
  "reviewLog": []
}
```

`mastery` 取值：`unknown`（未学）/ `weak`（自测或复习暴露薄弱）/ `ok`（通过自测）/ `solid`（复习中再次验证牢固）。

## 第五步：交付使用说明

规划写完后，明确告诉用户日常怎么用：

- **每天开始学习**：说"继续学习"或执行 `/learn-next`（DSH）→ 生成当天的图文课程 `day-NN.md`；
- **复习**：说"复习"或 `/learn-review` → 渐进式测验 + 查漏；
- **查看进度**：直接打开 `progress.json` 或问"我学到哪了"。

最后**立即询问用户是否现在就开始 D1**——如果用户要开始，直接衔接 learn-lesson skill 生成第一天课程。

## 设计原则

细节方法论（为什么这样拆解、寓言法完整原理）见 `references/method.md`。三条底线：

1. **宁少勿多**：每天的内容量以"当日自测能在 10 分钟内做完"为上限。用户半途而废的最常见原因是 D1 就被塞爆。
2. **依赖即顺序**：绝不在先修知识点未完成时安排后续内容。
3. **标注胜于沉默**：所有默认假设写出来，用户才有机会纠正。
